Project Description

In this section we present our project proposal, including information on our dataset. We then explain why we did the choises that we made in developing our project, such as how SAM3 and YOLO26 were trained. We finish the secion by poiting readers to explore some of the other sections that we have in the website or by reading our paper!

Project Proposal

Our original topic consisted of developing an object detection algorithm with the intended application being using it on an aerial vehicle (a drone). However, in our preliminary research, a set of restrictions arose in the form of College policies that would have prevented being able to test this model. Thus we decided to pivot sideways and instead of using aerial footage, we focused on terrestrial footage of streets.
With that idea present, our finalized topic at the time of the proposal was to compare the models of SAM3 and YOLO26 for their use in the field of autonomous vehicles. Particularly with a focus of using them for inferring in real time.

Dataset

We used the BDD100k dataset for our project. It was chosen over other datasets because it has ground truth values for both instance segmentation models (SAM3) and for bounding box models (YOLO26). Ground truth meansThis dataset includes a lot of videos and image frames from dash cam footage from around the US.
We in particular used the BDD10k image dataset, this was chosen over the other versions of the dataset because it has only image data, and one of our models (SAM3), is not super efficient at handling them. The 10000 images were divided into two, a train/fine-tuning folder with about 8000 images and a validating folder with the other 2000. In particular we focused on `car` data over other options to limit the scope of our project to have a single class that we can more easily quantify on, rather than have multiple options that might reduce accurary in our already limited training dataset.

Design Choices


YOLO26

We used the ultralytics library to implement YOLO26, and because of that we also used their training function. We fine-tuned YOLO26 on 100 epochs with the full fine-tuning subset as its batch size. Images were resized to 640x640px thorugh training, this was chosen over 480x480px (used in the original YOLO) because 640x640px is the size used in inference in the current version of YOLO26.
What all of these numbers and definitions mean is that YOLO26 read each of the 8000 images 100 times when training, leading to it gaining a better understanding of the car class, than it had before. Overall training took 4.9 hours using the Carleton College CS department research computers.

SAM3

We used the code presented in the original SAM3 paper to fine-tune SAM3. Our original idea was to use the same amount of epochs and batch size as YOLO26 (100 epochs and full batch size). However due to the computational complexity of SAM3, we were only able to fine-tune the model on 5 epochs running on the full batch size. This was because after about 9 hours of fine-tuning on all epochs at around epoch 6, the computer would run out of RAM and shut down.
Thus, 5 epochs was decided as a point where we could actually finish running it and thus being the amount we used. Even through this (comparatively) lower amount of runs through the data, we still saw an increase of accuracy when compared to YOLO26

Open CV Model

Before examining the neural network architectures of YOLO26 and SAM 3, we implemented a traditional computer vision algorithm using Python and OpenCV. Rather than learning features from training data, this algorithm uses explicitly defined rules to locate vehicles with taillight detection using OpenCV's inRange() method and a graph-based optimization algorithm called GrabCut to segment them.
